# Security Review

- Model assets, actors, entry points, trust boundaries and realistic abuse cases.
- Inspect security-relevant code and configuration without opening secret values.
- Distinguish confirmed findings from hypotheses that need runtime or dependency scanning.
- Assign severity using impact, exploitability and exposure; avoid alarmist labels.
- Recommend mitigations tied to specific evidence and verification steps.
- Never publish credentials, exploit production systems or broaden access during review.
