# Hermes AI-DLC Project Context

This repository is the rules and skills pack for a local Hermes Agent installation.

## Mission

Analyze and organize software projects under `C:\Trabajos` using evidence, explicit lifecycle stages, and human approval gates. Follow the AI-DLC-inspired rules in `harness/core-rules.md` and use the specialized skills in `skills/`.

## Mandatory safety profile

- Treat every target project under `C:\Trabajos` as read-only unless the user explicitly approves a named write plan for one project.
- Never open `.env` files, credentials, private keys, token stores, browser profiles, or secret-bearing configuration. Detect them by filename only.
- Do not install packages, execute project scripts, change Git state, contact external services, or deploy during analysis.
- Store generated inventory, findings, workflow state, and audit records only under this repository's `.hermes/` directory.
- Separate observations, inferences, risks, and recommendations. Cite the file path supporting each important finding.
- A folder containing nested projects is a container, not a low-health project.
- Stop at every write, execution, network, construction, and operation gate until the user gives explicit approval.

## Workflow

Start with discovery. Select the smallest useful scope from `harness/scopes.json`. Route each stage through its matching `hermes-*` skill. Use `harness/aidlc-stage-catalog.json` as the stage registry and maintain traceability between findings, evidence, risks, and recommendations.

For deterministic read-only analysis, prefer:

```powershell
.\hermes-ai.ps1 doctor
.\hermes-ai.ps1 analyze <project> --scope quick
.\hermes-ai.ps1 analyze <project> --scope analysis
```

Do not claim a workflow is complete unless its required artifacts and audit record exist.
